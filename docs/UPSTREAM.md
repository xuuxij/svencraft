# Upstream: the engine and game forks

`engine/` and `game/` are plain clones of their upstream repositories. Our changes live in their working trees,
**uncommitted**, on top of the upstream commit each clone has checked out (its `HEAD`). That keeps merging
upstream simple (see below) and `git -C engine status` / `git -C game status` always show exactly what is ours.
The GitHub repo of this project stores those working trees as they are on disk, with the upstream submodules as
gitlinks; the local `engine/.git` and `game/.git` are not part of it (docs/PUBLISHING.md).

## Merging upstream later

`tools/merge_branch.py <repo> <ref> [--base <commit>] [--exclude <glob> ...] [--dry]` applies the difference
between `<base>` (default: the clone's `HEAD`) and `<ref>` to the uncommitted working tree, file by file: files we
never touched are taken from upstream, files both sides changed get a 3-way `git merge-file` with conflict markers
where the same lines changed, files deleted upstream go only if we never changed them. Line endings follow our
copy. It prints a summary and exits 1 when conflicts are left. Always try `--dry` first, and back the working tree
up (copy the clone folder elsewhere) before a big merge.

**The game's extra branches** (`hlfixed`, `opforfixed`), after upstream changes them:

```sh
git -C game fetch origin hlfixed opforfixed
python tools/merge_branch.py game origin/hlfixed --dry
python tools/merge_branch.py game origin/hlfixed
python tools/merge_branch.py game origin/opforfixed --exclude "android/*" --exclude mod_options.txt
```

Tip: passing the branch commit merged last time as the base (`--base 9352fba` for hlfixed, `--base dffe28c` for
opforfixed, then the newer ones) applies only what changed upstream since; without it, files the branch added
whose upstream copy changed meanwhile are reported as conflicts and left alone. Note the merged commits here
each time.

**The master branch** (engine or game):

```sh
git -C engine fetch origin master
python tools/merge_branch.py engine origin/master --dry
python tools/merge_branch.py engine origin/master
# resolve conflicts (search for "<<<<<<< ours"), build, test, then move the base:
git -C engine reset -q origin/master          # mixed reset: HEAD + index only, the working tree is untouched
git -C engine submodule update --init --recursive
```

Moving `HEAD` to the merged commit keeps `git status` / `git diff` showing only our changes, and makes the next
merge start from there. Submodule pointer changes cannot be merged file by file (merge_branch.py reports them as
"changed upstream, missing here"); the `submodule update` after the reset checks out the new pins. After merging,
rebuild (`waf configure` again when upstream added source files), re-run the generators whose inputs changed
(`make_skillcfg.py` reads `game/dlls/game.cpp`), and update the table above.
